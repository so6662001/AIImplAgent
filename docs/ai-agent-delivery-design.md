## 一、现状分析与痛点识别

### 1.1 现有交付流程全景

```
项目安排 → 客户调研 → 交付计划 → 深度调研 → 模拟演练 → 培训 → 期初数据 → 建帐导数 → 启用帐套 → 跟进辅助 → 成果交付 → 售后跟进
   ①         ②          ③         ④          ⑤        ⑥        ⑦          ⑧          ⑨         ⑩          ⑪          ⑫
```

### 1.2 各环节痛点分析

| 环节 | 当前方式 | 核心痛点 | 耗时占比(估) |
|------|---------|---------|-------------|
| ①项目安排 | 人工调度，凭经验分配PM | 分配不均，难以全局优化 | 2% |
| ②客户调研 | PM电话/现场沟通 | 调研模板不统一，信息遗漏 | 8% |
| ③交付计划 | PM手工制作文档 | 文档格式不一，耗时久 | 5% |
| ④深度调研 | 团队进场，手工整理分析 | 分析维度多、整理工作量大 | 15% |
| ⑤模拟演练 | 手动配置演示环境 | 环境准备慢，场景覆盖不全 | 10% |
| ⑥培训 | 人工培训，重复讲解 | 人力成本极高，效果参差 | 15% |
| ⑦期初数据 | 手工整理、核对 | 数据量大、错误率高 | 10% |
| ⑧建帐导数 | 手工操作 | 操作繁琐、易出错 | 8% |
| ⑨启用帐套 | 人工检查确认 | 检查项多、遗漏风险 | 3% |
| ⑩跟进辅助 | 驻场人员 | 人力成本最高 | 12% |
| ⑪成果交付 | 人工编写报告 | 数据汇总慢、文档工作量大 | 5% |
| ⑫售后跟进 | 人工接线/远程 | 重复问题多、响应慢 | 7% |

### 1.3 关键问题总结

1. **重复性工作占比高**：模板文档生成、数据整理校验、常见问题解答等大量重复劳动
2. **经验难以沉淀**：PM个人经验难以标准化传承
3. **信息孤岛**：各环节信息传递依赖人工，存在断层
4. **质量不稳定**：强依赖个人能力，交付质量波动大
5. **响应效率低**：培训与售后均需人工实时响应

## 二、AI介入可行性评估矩阵

### 2.1 评估维度说明

- **AI替代度**：该环节工作可被AI替代的程度（高/中/低）
- **技术成熟度**：当前AI技术实现该能力的成熟度（高/中/低）
- **业务价值**：AI介入后带来的降本增效价值（高/中/低）
- **实施难度**：技术实施与业务适配的难度（高/中/低）

### 2.2 评估矩阵

| 环节 | AI替代度 | 技术成熟度 | 业务价值 | 实施难度 | 优先级 | 建议策略 |
|------|---------|-----------|---------|---------|--------|---------|
| ①项目安排 | 中 | 高 | 中 | 低 | P2 | AI辅助推荐，人工决策 |
| ②客户调研 | 中 | 高 | 高 | 中 | P1 | AI生成调研框架+智能问卷 |
| ③交付计划 | 高 | 高 | 高 | 低 | P0 | AI自动生成，人工审核 |
| ④深度调研 | 中 | 中 | 高 | 中 | P1 | AI辅助分析+报告生成 |
| ⑤模拟演练 | 中 | 中 | 中 | 高 | P2 | AI生成演练场景+环境配置 |
| ⑥培训 | 高 | 高 | 高 | 中 | P0 | AI培训助手+智能问答 |
| ⑦期初数据 | 高 | 高 | 高 | 中 | P0 | AI数据清洗校验 |
| ⑧建帐导数 | 高 | 高 | 高 | 低 | P1 | AI自动化执行 |
| ⑨启用帐套 | 中 | 高 | 中 | 低 | P2 | AI检查清单自动化 |
| ⑩跟进辅助 | 高 | 高 | 高 | 中 | P0 | AI智能客服替代驻场 |
| ⑪成果交付 | 高 | 高 | 中 | 低 | P1 | AI自动生成报告 |
| ⑫售后跟进 | 高 | 高 | 高 | 低 | P0 | AI客服+工单智能流转 |

### 2.3 优先级分组

- **P0（立即启动）**：③交付计划生成、⑥智能培训、⑦数据清洗、⑩智能跟进、⑫智能售后
- **P1（次期推进）**：②调研辅助、④深度分析、⑧自动建帐、⑪报告生成
- **P2（远期规划）**：①智能调度、⑤演练生成、⑨上线检查

### 3.2 核心设计原则

1. **人机协同（Human-in-the-Loop）**：AI辅助不替代，关键决策必须有人工审核确认节点
2. **知识驱动**：以钢铁行业交付知识库为核心，持续积累沉淀
3. **可编排**：智能体独立运行，也可组合编排成复杂工作流
4. **渐进增强**：从辅助到半自动到自动，逐步提升AI参与度
5. **可观测**：所有AI决策过程可追溯、可审计

## 四、各智能体详细设计

### 4.1 项目调度智能体（Project Dispatch Agent）

**对应环节**：① 项目安排，确定项目经理

**核心能力**：
- 基于项目特征（客户规模、行业细分、系统复杂度）和PM画像（技能矩阵、当前负载、历史业绩、客户评价）进行智能匹配
- 输出推荐的PM人选及匹配理由

**输入**：
```
{
  "project_info": {
    "customer_name": "客户名称",
    "industry_segment": "钢贸/钢厂/加工中心/...",
    "estimated_scale": "大/中/小",
    "modules": ["进销存", "财务", "仓储", ...],
    "special_requirements": "特殊需求描述",
    "expected_start_date": "预计启动日期",
    "region": "所在地区"
  }
}
```

**输出**：
```
{
  "recommended_pms": [
    {
      "pm_id": "PM001",
      "name": "张三",
      "match_score": 92,
      "match_reasons": [
        "具有5个钢贸企业交付经验",
        "当前负载率60%，有余量",
        "距离客户所在地较近"
      ],
      "risk_notes": "近期有一个项目即将上线，需关注时间冲突"
    }
  ],
  "schedule_suggestion": {
    "recommended_start": "2026-05-01",
    "estimated_duration": "45天",
    "key_milestones": [...]
  }
}
```

**AI策略**：
- 使用规则引擎 + LLM混合模式
- 硬约束（资质、可用性）用规则过滤，软约束（匹配度）用LLM评分
- 持续学习：项目完成后的评价数据反馈到匹配模型

### 4.2 调研分析智能体（Research Agent）

**对应环节**：② 联系客户做项目调研 + ④ 深度调研

**核心能力**：
- 根据客户行业/规模/经营模式，自动生成定制化调研问卷和访谈提纲
- 实时辅助PM进行调研：语音转文字 → 关键信息提取 → 结构化沉淀
- 自动生成客户背景分析报告

**子能力拆分**：

#### 4.2.1 调研问卷生成器

**Prompt模板设计思路**：
```
角色：你是一位钢铁行业管理软件的资深实施顾问
任务：根据以下客户初步信息，生成一份结构化的调研问卷

客户信息：
- 企业类型：{enterprise_type} (钢贸商/钢厂/加工中心/综合服务商)
- 预估规模：{scale}
- 意向模块：{modules}

要求覆盖以下维度：
1. 经营模式分析（直营/代理/混合，内贸/外贸）
2. 经营品类（板材/型材/管材/特钢/不锈钢等，规格/材质/品牌分布）
3. 库存状况（库存量级，仓库数量与分布，库存周转率）
4. 销售状况（月均销售量/金额，定价模式，结算方式）
5. 客户群体（客户数量，客户类型分布，主要大客户）
6. 组织架构（部门设置，人员规模，关键岗位）
7. 现有IT系统（在用系统，痛点，数据情况）
8. 管理诉求与目标

请根据企业类型重点调整问卷侧重点。
```

#### 4.2.2 调研信息结构化引擎

**能力说明**：将PM录入的非结构化调研记录（文字/语音转文字），自动提取并填充到标准化的客户画像模型中。

**客户画像数据模型**：
```
CustomerProfile {
  // 基本信息
  basic_info: {
    company_name, legal_person, registered_capital,
    establishment_date, region, address
  }
  // 经营模式

    trade_mode: "直营|代理|混合",

    main_business_description: "..."
  }
  // 经营品类
  product_categories: [
    { category, sub_category, brands[], specifications[], proportion }
  ]
  // 库存状况
  inventory: {
    total_volume, warehouse_count, warehouses[],
    turnover_rate, management_method
  }
  // 销售状况
  sales: {
    monthly_volume, monthly_amount, pricing_model,
    settlement_methods[], credit_policy
  }
  // 客户群体
  customer_base: {
    total_count, customer_types[], top_customers[],

  // 组织架构

    departments[], total_staff, key_positions[],

  // 现有系统

  // 项目目标
  project_goals: {
    management_goals: [],    // 管理目标
    process_goals: [],       // 流程目标
    efficiency_goals: [],    // 效率目标
    risk_control_goals: [],  // 风控目标
    other_goals: []          // 其他目标
  }
}
```

#### 4.2.3 背景分析报告生成器

**能力说明**：基于结构化的客户画像，自动生成完整的《客户背景分析报告》，包含：
- 企业概况与行业定位
- 经营模式分析与建议
- 业务流程梳理（输出标准流程图描述）
- 项目目标总结与优先级建议
- 交付风险预评估
- 项目成果定义建议

### 4.3 计划生成智能体（Plan Generator Agent）

**对应环节**：③ 项目交付计划制作

**核心能力**：
- 基于客户画像、项目范围、历史同类项目数据，自动生成项目交付计划
- 包含：里程碑、任务分解（WBS）、资源需求、时间排期、风险预案

**输入**：
```
{
  "customer_profile": { ... },        // 来自调研分析智能体
  "project_scope": {
    "modules": ["进销存", "财务", "仓储"],
    "customization_level": "标准/轻度定制/深度定制",
    "integration_requirements": ["ERP对接", "银行接口"]
  },
  "constraints": {
    "deadline": "2026-08-01",
    "budget": "...",
    "available_resources": [...]
  }
}
```

**输出**：
```
{
  "project_plan": {
    "milestones": [
      { "name": "调研完成", "date": "...", "deliverables": [...] },
      { "name": "模拟演练通过", "date": "...", "deliverables": [...] },
      { "name": "培训完成", "date": "...", "deliverables": [...] },
      { "name": "正式上线", "date": "...", "deliverables": [...] },
      { "name": "交付验收", "date": "...", "deliverables": [...] }
    ],
    "wbs": [...],           // 详细任务分解
    "resource_plan": [...],  // 人员与资源计划
    "risk_plan": [...],      // 风险预案
    "gantt_data": [...]      // 甘特图数据
  }
}
```

**AI策略**：
- RAG检索历史同类项目计划作为参考
- LLM基于参考案例 + 当前项目约束生成新计划
- 内置钢铁行业交付最佳实践知识库
- 自动识别高风险节点并标注

### 4.4 模拟演练智能体（Simulation Agent）

**对应环节**：⑤ 模拟演练软件系统

**核心能力**：
- 根据客户业务场景自动生成模拟数据和测试用例
- 自动化场景配置：根据客户品类/流程特点配置演示环境
- 演练偏差检测：对比预期结果与实际演练结果

**核心功能**：

1. **模拟数据生成**
   - 根据客户经营品类，自动生成仿真的产品目录、客户档案、供应商档案
   - 根据库存量级和销售规模生成合理的模拟业务数据
   - 保证数据间的逻辑一致性（例如：库存数 = 入库数 - 出库数）

2. **演练场景脚本生成**
   - 基于客户业务流程，自动编排演练场景脚本
   - 覆盖核心业务路径 + 异常/边界场景
   - 输出step-by-step的操作指南

3. **演练结果评估**
   - 演练过程中自动记录操作日志
   - 与预期结果对比，标记偏差项
   - 生成《模拟演练评估报告》

### 4.5 培训助手智能体（Training Agent）

**对应环节**：⑥ 培训

**核心能力**：
- 根据岗位角色自动生成针对性的培训材料
- AI实时问答：培训期间和培训后的即时答疑
- 学习效果评估与个性化补强

**子系统设计**：

#### 4.5.1 培训内容生成引擎

**按角色分层**：
```
┌──────────────────────────────────────────┐
│              培训内容矩阵                  │
├──────────┬──────────┬──────────┬─────────┤
│  角色     │ 内容重点   │ 深度     │ 形式    │
├──────────┼──────────┼──────────┼─────────┤
│ 高层管理  │ 报表/看板  │ 概览     │ 图文简报 │
│ 中层管理  │ 审批/分析  │ 应用级   │ 操作手册 │
│ 业务骨干  │ 全流程操作 │ 精通级   │ 视频+实操│
│ 普通操作  │ 岗位操作   │ 操作级   │ 操作卡片 │
│ IT运维   │ 系统配置   │ 技术级   │ 技术文档 │
└──────────┴──────────┴──────────┴─────────┘
```

**生成内容类型**：
- 操作手册（图文并茂，step-by-step）
- 操作视频脚本（可配合录屏工具自动生成）
- 岗位操作速查卡（一页纸快速参考）
- 考核题库（选择题/操作题/场景题）

#### 4.5.2 智能培训问答Bot

**技术方案**：
- 基于RAG（检索增强生成）架构
- 知识来源：产品文档 + 操作手册 + 历史QA + 行业知识
- 支持多轮对话，理解上下文
- 支持截图识别：用户截图提问，AI识别界面并给出操作指引

**对话示例**：
```
用户：钢卷入库的时候怎么录入炉号和捆号？
Bot：在入库单界面，您可以按以下步骤操作：
     1. 进入【仓储管理】→【入库管理】→【新建入库单】
     2. 选择品类为"钢卷"后，系统会自动显示炉号和捆号字段
     3. 炉号在"炉批号"字段录入，捆号在"件号"字段录入
     4. 如果是批量入库，可以使用"批量导入"功能...
     [附操作截图]
```

#### 4.5.3 学习效果评估

- 自动生成岗位考核试卷

### 4.6 数据治理智能体（Data Governance Agent）

**对应环节**：⑦ 准备期初数据 + ⑧ 建帐套并导入数据

**工作流设计**：

#### 4.6.1 数据清洗规则（钢铁行业特化）

```
钢铁行业数据清洗规则集:

1. 品名标准化
   - "热轧卷板" / "热轧卷" / "热卷" / "HRC" → 标准名称："热轧卷板"
   - 建立钢铁品类同义词库

2. 规格标准化
   - "3.0*1250*C" / "3.0×1250×C" / "3*1250*卷" → "3.0*1250*C"
   - 厚度*宽度*长度(或C表示卷) 的标准格式验证

3. 材质标准化
   - "Q235" / "Q235B" / "q235b" → "Q235B"
   - 国标材质代码校验

4. 钢厂名称标准化
   - "宝钢" / "宝山钢铁" / "上海宝钢" → "宝山钢铁股份有限公司"

5. 重量单位统一
   - 吨/千克/公斤 统一换算

6. 仓库名称匹配
   - 模糊匹配到系统标准仓库编码

7. 客商名称去重
   - 识别同一客商的不同叫法，合并处理

8. 勾稽关系校验
   - 库存数量 = Σ入库 - Σ出库
   - 应收余额 = Σ销售 - Σ收款
   - 期初余额 + 本期发生 = 期末余额

### 6.4 AI智能体运行时核心设计

// 智能体基础接口设计思路
public interface Agent {
    String getId();
    String getName();
    AgentType getType();
    AgentCapability[] getCapabilities();
    
    // 执行入口
    AgentResult execute(AgentContext context, AgentRequest request);
    
    // 流式执行（用于对话场景）
    Flux<AgentEvent> executeStream(AgentContext context, AgentRequest request);
}

// 智能体上下文
public class AgentContext {
    private String projectId;
    private String userId;
    private ProjectContext projectContext;  // 项目全局上下文
    private ConversationHistory history;    // 对话历史
    private Map<String, Object> variables;  // 运行时变量
}

// 智能体编排引擎
public interface AgentOrchestrator {
    // 执行编排好的工作流
    WorkflowResult executeWorkflow(String workflowId, ProjectContext context);
    
    // 根据用户意图自动选择并调用合适的智能体
    AgentResult dispatch(String userIntent, AgentContext context);
}

│  ├─ 历史项目案例
│  ├─ 典型问题解决方案
│  ├─ 交付经验总结
│  └─ 客户反馈汇总
│
└─ 项目私有层
   ├─ 特定客户的调研数据
   ├─ 特定项目的交付文档
   └─ 特定客户的QA记录
```

**向量化与检索策略**：
- 文档分块：按语义段落分块，保留上下文（chunk_size=512, overlap=64）
- 多路召回：关键词检索(BM25) + 语义检索(向量) + 知识图谱检索
- 重排序：使用Reranker模型对召回结果精排
- 权限隔离：项目私有层数据按项目ID隔离

## 八、实施路径建议

### 8.1 分阶段实施计划

#### 第一阶段：基础设施 + P0智能体

**目标**：搭建AI智能体基础平台，上线最高价值的5个智能体

**范围**：
1. AI智能体基础平台搭建
   - LLM网关服务（支持多模型切换）
   - RAG检索服务 + 向量数据库
   - 知识库管理后台
   - Agent运行时引擎
   - AI对话前端组件

2. P0智能体开发
   - **计划生成Agent**（③）— 入手难度最低，见效快
   - **培训助手Agent**（⑥）— 降本效果明显
   - **数据治理Agent**（⑦）— 技术成熟，价值高
   - **现场辅助Agent**（⑩）— 降低驻场成本
   - **售后服务Agent**（⑫）— 独立性强，易落地

**技术关键项**：
- 钢铁行业知识库构建（术语、品类、业务流程）
- 历史项目数据整理与向量化
- 产品操作文档结构化

#### 第二阶段：P1智能体 + 流程串联

**目标**：补齐核心智能体，实现全流程AI协同

**范围**：
1. P1智能体开发
   - **调研分析Agent**（②④）
   - **帐套管理Agent**（⑧）
   - **交付报告Agent**（⑪）

2. 智能体编排引擎
   - 实现智能体间的上下文传递
   - 实现全流程自动编排
   - 人工审核节点集成

3. 知识库持续丰富
   - 项目经验自动沉淀
   - 问题解决方案自动归档

#### 第三阶段：P2智能体 + 智能化升级

**目标**：全面智能化，持续优化

**范围**：
1. P2智能体开发
   - **项目调度Agent**（①）
   - **演练配置Agent**（⑤）
   - **上线检查Agent**（⑨）

2. 智能化升级
   - 多模态能力（语音输入、图片识别）
   - 预测性分析（项目风险预测、客户流失预测）
   - 智能体自我学习与优化

### 8.2 各阶段价值预期

| 阶段 | 人力节省预估 | 效率提升预估 | 关键价值 |
|------|------------|------------|---------|
| 第一阶段 | 20-30% | 30-40% | 培训/售后/数据处理人力大幅减少 |
| 第二阶段 | 40-50% | 50-60% | 全流程提效，经验标准化 |
| 第三阶段 | 50-60% | 60-80% | 预测性运维，主动服务 |

## 九、风险与应对策略

### 9.1 技术风险

| 风险 | 影响 | 应对策略 |
|------|------|---------|
| LLM输出不准确/幻觉 | 生成错误方案影响交付 | 关键环节设人工审核；使用RAG约束回答范围；置信度评分低于阈值自动标记 |
| 数据安全泄露 | 客户敏感数据外泄 | 数据脱敏处理；使用私有化部署LLM（如本地部署开源模型）；数据按项目隔离 |
| LLM API不稳定 | 服务中断 | 多模型备份（主备切换）；关键功能降级方案（退回人工模式）|
| 向量检索精度不够 | AI回答质量差 | 多路召回+重排序；持续优化分块策略；人工标注优化 |

### 9.2 业务风险

| 风险 | 影响 | 应对策略 |
|------|------|---------|
| 用户排斥AI | 推广困难 | 先从内部PM试用，再推广到客户；AI作为辅助工具而非替代 |
| 知识库冷启动 | 初期AI表现差 | 组织老PM进行知识贡献；历史项目资料批量导入 |
| 过度依赖AI | 团队能力退化 | 保持关键环节人工参与；定期进行无AI演练 |
| 行业特殊性 | 通用AI不适用 | 持续投入行业知识库建设；行业专家参与Prompt调优 |

### 9.3 LLM选型建议

| 场景 | 推荐方案 | 理由 |
|------|---------|------|
| 文档生成/报告撰写 | 通义千问/文心一言/GPT-4 | 中文表达能力强 |
| 数据分析/代码生成 | DeepSeek / GPT-4 | 逻辑推理能力强 |
| 知识问答/客服 | 私有化部署 Qwen/GLM + RAG | 数据安全，成本可控 |
| 数据清洗/格式化 | 轻量级模型(Qwen-7B) | 任务明确，无需大模型 |

> **成本控制建议**：对于高频低复杂度场景（如售后问答），优先使用私有化部署的开源模型降低Token成本；对于低频高复杂度场景（如计划生成），可使用商业API获得更好效果。
