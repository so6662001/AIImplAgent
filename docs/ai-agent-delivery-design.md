## 一、现状分析与痛点识别

### 1.1 现有交付流程全景

```
项目安排 → 客户调研 → 交付计划 → 深度调研 → 模拟演练 → 培训 → 期初数据 → 建帐导数 → 启用帐套 → 跟进辅助 → 成果交付 → 售后跟进
   ①         ②          ③         ④          ⑤        ⑥        ⑦          ⑧          ⑨         ⑩          ⑪          ⑫
```

### 1.2 各环节痛点分析

| 环节 | 当前方式 | 核心痛点 | 耗时占比(估) |
|------|---------|---------|-------------|
| ①项目安排 | 人工调度，凭经验分配PM | 分配不均，难以全局优化 | 2% |
| ②客户调研 | PM电话/现场沟通 | 调研模板不统一，信息遗漏 | 8% |
| ③交付计划 | PM手工制作文档 | 文档格式不一，耗时久 | 5% |
| ④深度调研 | 团队进场，手工整理分析 | 分析维度多、整理工作量大 | 15% |
| ⑤模拟演练 | 手动配置演示环境 | 环境准备慢，场景覆盖不全 | 10% |
| ⑥培训 | 人工培训，重复讲解 | 人力成本极高，效果参差 | 15% |
| ⑦期初数据 | 手工整理、核对 | 数据量大、错误率高 | 10% |
| ⑧建帐导数 | 手工操作 | 操作繁琐、易出错 | 8% |
| ⑨启用帐套 | 人工检查确认 | 检查项多、遗漏风险 | 3% |
| ⑩跟进辅助 | 驻场人员 | 人力成本最高 | 12% |
| ⑪成果交付 | 人工编写报告 | 数据汇总慢、文档工作量大 | 5% |
| ⑫售后跟进 | 人工接线/远程 | 重复问题多、响应慢 | 7% |

### 1.3 关键问题总结

1. **重复性工作占比高**：模板文档生成、数据整理校验、常见问题解答等大量重复劳动
2. **经验难以沉淀**：PM个人经验难以标准化传承
3. **信息孤岛**：各环节信息传递依赖人工，存在断层
4. **质量不稳定**：强依赖个人能力，交付质量波动大
5. **响应效率低**：培训与售后均需人工实时响应

## 二、AI介入可行性评估矩阵

### 2.1 评估维度说明

- **AI替代度**：该环节工作可被AI替代的程度（高/中/低）
- **技术成熟度**：当前AI技术实现该能力的成熟度（高/中/低）
- **业务价值**：AI介入后带来的降本增效价值（高/中/低）
- **实施难度**：技术实施与业务适配的难度（高/中/低）

### 2.2 评估矩阵

| 环节 | AI替代度 | 技术成熟度 | 业务价值 | 实施难度 | 优先级 | 建议策略 |
|------|---------|-----------|---------|---------|--------|---------|
| ①项目安排 | 中 | 高 | 中 | 低 | P2 | AI辅助推荐，人工决策 |
| ②客户调研 | 中 | 高 | 高 | 中 | P1 | AI生成调研框架+智能问卷 |
| ③交付计划 | 高 | 高 | 高 | 低 | P0 | AI自动生成，人工审核 |
| ④深度调研 | 中 | 中 | 高 | 中 | P1 | AI辅助分析+报告生成 |
| ⑤模拟演练 | 中 | 中 | 中 | 高 | P2 | AI生成演练场景+环境配置 |
| ⑥培训 | 高 | 高 | 高 | 中 | P0 | AI培训助手+智能问答 |
| ⑦期初数据 | 高 | 高 | 高 | 中 | P0 | AI数据清洗校验 |
| ⑧建帐导数 | 高 | 高 | 高 | 低 | P1 | AI自动化执行 |
| ⑨启用帐套 | 中 | 高 | 中 | 低 | P2 | AI检查清单自动化 |
| ⑩跟进辅助 | 高 | 高 | 高 | 中 | P0 | AI智能客服替代驻场 |
| ⑪成果交付 | 高 | 高 | 中 | 低 | P1 | AI自动生成报告 |
| ⑫售后跟进 | 高 | 高 | 高 | 低 | P0 | AI客服+工单智能流转 |

| ⑬智能录入辅助 | 高 | 高 | 高 | 中 | P0 | AI实时答疑+操作视频推送 |

### 2.3 优先级分组

- **P0（立即启动）**：③交付计划生成、⑥智能培训、⑦数据清洗、⑩智能跟进、⑫智能售后、**⑬智能录入辅助**
- **P1（次期推进）**：②调研辅助、④深度分析、⑧自动建帐、⑪报告生成
- **P2（远期规划）**：①智能调度、⑤演练生成、⑨上线检查

### 3.2 核心设计原则

1. **人机协同（Human-in-the-Loop）**：AI辅助不替代，关键决策必须有人工审核确认节点
2. **知识驱动**：以钢铁行业交付知识库为核心，持续积累沉淀
3. **可编排**：智能体独立运行，也可组合编排成复杂工作流
4. **渐进增强**：从辅助到半自动到自动，逐步提升AI参与度
5. **可观测**：所有AI决策过程可追溯、可审计

## 四、各智能体详细设计

### 4.1 项目调度智能体（Project Dispatch Agent）

**对应环节**：① 项目安排，确定项目经理

**核心能力**：
- 基于项目特征（客户规模、行业细分、系统复杂度）和PM画像（技能矩阵、当前负载、历史业绩、客户评价）进行智能匹配
- 输出推荐的PM人选及匹配理由

**输入**：
```
{
  "project_info": {
    "customer_name": "客户名称",
    "industry_segment": "钢贸/钢厂/加工中心/...",
    "estimated_scale": "大/中/小",
    "modules": ["进销存", "财务", "仓储", "MES", "智能财务", "智能采购", "智能录入", ...],
    "special_requirements": "特殊需求描述",
    "expected_start_date": "预计启动日期",
    "region": "所在地区"
  }
}
```

**输出**：
```
{
  "recommended_pms": [
    {
      "pm_id": "PM001",
      "name": "张三",
      "match_score": 92,
      "match_reasons": [
        "具有5个钢贸企业交付经验",
        "当前负载率60%，有余量",
        "距离客户所在地较近"
      ],
      "risk_notes": "近期有一个项目即将上线，需关注时间冲突"
    }
  ],
  "schedule_suggestion": {
    "recommended_start": "2026-05-01",
    "estimated_duration": "45天",
    "key_milestones": [...]
  }
}
```

**AI策略**：
- 使用规则引擎 + LLM混合模式
- 硬约束（资质、可用性）用规则过滤，软约束（匹配度）用LLM评分
- 持续学习：项目完成后的评价数据反馈到匹配模型

### 4.2 调研分析智能体（Research Agent）

**对应环节**：② 联系客户做项目调研 + ④ 深度调研

**核心能力**：
- 根据客户行业/规模/经营模式，自动生成定制化调研问卷和访谈提纲
- 实时辅助PM进行调研：语音转文字 → 关键信息提取 → 结构化沉淀
- 自动生成客户背景分析报告

**子能力拆分**：

#### 4.2.1 调研问卷生成器

**Prompt模板设计思路**：
```
角色：你是一位钢铁行业管理软件的资深实施顾问
任务：根据以下客户初步信息，生成一份结构化的调研问卷

客户信息：
- 企业类型：{enterprise_type} (钢贸商/钢厂/加工中心/综合服务商)
- 预估规模：{scale}
- 意向模块：{modules}

要求覆盖以下维度：
1. 经营模式分析（直营/代理/混合，内贸/外贸）
2. 经营品类（板材/型材/管材/特钢/不锈钢等，规格/材质/品牌分布）
3. 生产能力（仅生产型企业：产线数量/类型/产能/排班/MES现状/质量标准）
4. 库存与仓储（库存量级，仓库数量/面积(㎡)/行车数量与吨位，库存周转率）
5. 销售状况（月均销售量/金额，定价模式，结算方式，销售模式）
6. 客户群体（客户数量，客户类型分布，主要大客户）
7. 组织架构（部门设置，人员规模，关键岗位）
8. 现有IT系统（在用系统，痛点，数据情况）
9. 目标模块需求（进销存/财务/仓储/MES/智能财务/智能采购/智能录入）
10. 管理诉求与目标

请根据企业类型重点调整问卷侧重点：
- 生产型企业(钢厂/加工中心)重点覆盖 产线信息、MES需求、质量管理
- 现货批发企业(钢贸商)重点覆盖 仓库数量/面积/行车数、库存管理
- 所有企业均需采集 智能财务/智能采购/智能录入 的需求深度
```

**能力说明**：将PM录入的非结构化调研记录（文字/语音转文字），自动提取并填充到标准化的客户画像模型中。

> - **综合服务商**：两者兼顾

#### 4.2.3 背景分析报告生成器

- 项目成果定义建议

### 4.3 计划生成智能体（Plan Generator Agent）

**对应环节**：③ 项目交付计划制作

**核心能力**：
- 基于客户画像、项目范围、历史同类项目数据，自动生成项目交付计划
- 包含：里程碑、任务分解（WBS）、资源需求、时间排期、风险预案

**输入**：
```
{
  "customer_profile": { ... },        // 来自调研分析智能体
  "project_scope": {
    "modules": ["进销存", "财务", "仓储", "MES", "智能财务", "智能采购", "智能录入"],
    "customization_level": "标准/轻度定制/深度定制",
    "integration_requirements": ["ERP对接", "银行接口"]
  },
  "constraints": {
    "deadline": "2026-08-01",
    "budget": "...",
    "available_resources": [...]
  }
}
```

**输出**：
```
{
  "project_plan": {
    "milestones": [
      { "name": "调研完成", "date": "...", "deliverables": [...] },
      { "name": "模拟演练通过", "date": "...", "deliverables": [...] },
      { "name": "培训完成", "date": "...", "deliverables": [...] },
      { "name": "正式上线", "date": "...", "deliverables": [...] },
      { "name": "交付验收", "date": "...", "deliverables": [...] }
    ],
    "wbs": [...],           // 详细任务分解
    "resource_plan": [...],  // 人员与资源计划
    "risk_plan": [...],      // 风险预案
    "gantt_data": [...]      // 甘特图数据
  }
}
```

**AI策略**：
- RAG检索历史同类项目计划作为参考
- LLM基于参考案例 + 当前项目约束生成新计划
- 内置钢铁行业交付最佳实践知识库
- 自动识别高风险节点并标注

### 4.4 模拟演练智能体（Simulation Agent）

**对应环节**：⑤ 模拟演练软件系统

**核心能力**：
- 根据客户业务场景自动生成模拟数据和测试用例
- 自动化场景配置：根据客户品类/流程特点配置演示环境
- 演练偏差检测：对比预期结果与实际演练结果

**核心功能**：

1. **模拟数据生成**
   - 根据客户经营品类，自动生成仿真的产品目录、客户档案、供应商档案
   - 根据库存量级和销售规模生成合理的模拟业务数据
   - 保证数据间的逻辑一致性（例如：库存数 = 入库数 - 出库数）

2. **演练场景脚本生成**
   - 基于客户业务流程，自动编排演练场景脚本
   - 覆盖核心业务路径 + 异常/边界场景
   - 输出step-by-step的操作指南

3. **演练结果评估**
   - 演练过程中自动记录操作日志
   - 与预期结果对比，标记偏差项
   - 生成《模拟演练评估报告》

**AI出题策略**：

```

   │   AI基于常见错误和易混淆操作生成
   │
   ├─ 操作题 (30%) — 考察实际操作能力 ★核心
```

```
这是AI数据治理的核心难点，需要钢铁行业深度知识：

1. 品名标准化（同义词库）:
   ┌──────────────────┬───────────────────────────┐
   │ 标准品名          │ 同义词/别名                 │
   ├──────────────────┼───────────────────────────┤
   │ 热轧卷板          │ 热轧卷、热卷、HRC、热板      │
   │ 冷轧卷板          │ 冷轧卷、冷卷、CRC、冷板、SPCC│

   │ 无缝钢管          │ 无缝管、无缝                  │
   └──────────────────┴───────────────────────────┘

2. 规格标准化引擎:
   输入各种格式 → 解析 → 输出标准格式

   板材/卷板: 厚度*宽度*长度(或C)
     "3.0*1250*C"    → { 厚:3.0, 宽:1250, 长:"C(卷)" }  ✓ 标准
     "3.0×1250×C"    → 转换为 "3.0*1250*C"
     "3*1250*卷"     → 转换为 "3.0*1250*C"
     "3.0mm*1250mm*C"→ 转换为 "3.0*1250*C"

   型材: 规格型号
     "H200*200*8*12" → { H:200, B:200, tw:8, tf:12 }
     "HW200×200"     → 补全为 "H200*200*8*12"(查标准表)

   管材: 外径*壁厚*长度
     "Φ219*8*12000"  → { OD:219, WT:8, L:12000 }
     "219×8×12m"     → 转换为 "Φ219*8*12000"

   线材/建材: 直径
     "Φ8"/"φ8"/"8mm" → "Φ8"
   
3. 材质标准化引擎:
   "Q235"    → "Q235B"  (默认补全子级)
   "q235b"   → "Q235B"  (大写标准化)
   "Q345"    → "Q345B"  (默认补全子级)
   "SS400"   → "Q235B"  (日标转国标映射)
   "SPHC"    → 保留      (日标热轧通用，标记为进口)
   "DC01"    → 保留      (欧标，标记为进口)
   
   AI额外校验: 品名与材质是否匹配
   例: "螺纹钢" + "SPCC" → 告警（SPCC通常用于冷轧，不用于螺纹钢）

4. 钢厂名称标准化:
   使用B2中的钢厂名称库进行统一

5. 件重合理性校验(基于理论计算):
   板材理论重量 = 厚(mm) × 宽(mm) × 长(mm) × 密度(7.85g/cm³)
   偏差超过±5%标记为异常，提醒人工确认
```

#### 4.11.5 视频知识库建设方案

```
视频生产流程:

┌─────────┐    ┌─────────┐    ┌─────────┐    ┌─────────┐
│ 录屏采集  │───▶│ AI切片   │───▶│ 字幕生成 │───▶│ 索引入库  │
│          │    │ & 标注   │    │ & 翻译   │    │          │
└─────────┘    └─────────┘    └─────────┘    └─────────┘

1. 录屏采集:
   - 由实施团队在标准环境中录制各功能操作视频
   - 每个视频覆盖一个完整操作场景（3-5分钟）
   - 录制时使用标准化的操作步骤和解说脚本（由AI生成）

2. AI切片 & 标注:
   - AI自动识别视频中的操作步骤边界（基于画面变化检测）
   - 为每个切片打标签: 模块/功能/操作步骤/涉及字段
   - 生成切片时间戳索引

3. 字幕生成:
   - ASR自动生成字幕
   - AI校对字幕准确性（特别是钢铁行业术语）

4. 索引入库:
   - 视频元数据 + 切片索引 + 字幕文本 → 向量化入库
   - 建立 页面/字段 → 视频切片 的精确映射关系
   - 支持按关键词/语义 检索视频内容

视频更新策略:
   - 系统版本更新时，自动标记受影响的视频
   - 优先更新高频使用的视频
   - 支持增量录制（只录变更部分）
```

**与培训助手Agent(4.5)的协同**：
- 培训阶段：培训助手Agent使用完整视频进行系统培训
- 日常使用：智能录入Agent使用视频切片进行精准答疑
- 共享同一个视频知识库，避免重复建设
- 培训考核中的薄弱环节 → 自动关联到智能录入Agent的重点提示规则

```java
public interface AgentOrchestrator {
```

## 八、实施路径建议

### 8.1 分阶段实施计划

#### 第一阶段：基础设施 + P0智能体

**目标**：搭建AI智能体基础平台，上线最高价值的5个智能体

**范围**：
1. AI智能体基础平台搭建
   - LLM网关服务（支持多模型切换）
   - RAG检索服务 + 向量数据库
   - 知识库管理后台
   - Agent运行时引擎
   - AI对话前端组件

2. P0智能体开发
   - **计划生成Agent**（③）— 入手难度最低，见效快
   - **培训助手Agent**（⑥）— 降本效果明显
   - **数据治理Agent**（⑦）— 技术成熟，价值高
   - **现场辅助Agent**（⑩）— 降低驻场成本
   - **售后服务Agent**（⑫）— 独立性强，易落地
   - **智能录入Agent**（⑬）— 嵌入产品，降低用户学习成本，减少培训和售后压力

**技术关键项**：
- LLM网关搭建：GLM(客服/问答) + 通义千问(文档/分析) + Claude(推理/编排) 三模型路由
- 钢铁行业知识库构建（术语、品类、业务流程）
- **操作视频知识库建设**（录屏→AI切片→字幕→向量化索引）
- 历史项目数据整理与向量化
- 产品操作文档结构化

#### 第二阶段：P1智能体 + 流程串联

**目标**：补齐核心智能体，实现全流程AI协同

**范围**：
1. P1智能体开发
   - **调研分析Agent**（②④）
   - **帐套管理Agent**（⑧）
   - **交付报告Agent**（⑪）

2. 智能体编排引擎
   - 实现智能体间的上下文传递
   - 实现全流程自动编排
   - 人工审核节点集成

3. 知识库持续丰富
   - 项目经验自动沉淀
   - 问题解决方案自动归档

#### 第三阶段：P2智能体 + 智能化升级

**目标**：全面智能化，持续优化

**范围**：
1. P2智能体开发
   - **项目调度Agent**（①）
   - **演练配置Agent**（⑤）
   - **上线检查Agent**（⑨）

2. MES与智能模块深度集成
   - MES产线数据与交付系统打通
   - 智能财务 → AI自动生成凭证、异常检测、报表解读
   - 智能采购 → AI供应商推荐、价格预测、自动询价
   - 智能录入能力持续优化（基于用户行为数据迭代）

3. 智能化升级
   - 多模态能力（语音输入、图片识别）
   - 预测性分析（项目风险预测、客户流失预测）
   - 智能体自我学习与优化

### 8.2 各阶段价值预期

## 九、风险与应对策略

### 9.1 技术风险

| 风险 | 影响 | 应对策略 |
|------|------|---------|
| LLM输出不准确/幻觉 | 生成错误方案影响交付 | 关键环节设人工审核；使用RAG约束回答范围；置信度评分低于阈值自动标记 |
| 数据安全泄露 | 客户敏感数据外泄 | 数据脱敏处理；使用私有化部署LLM（如本地部署开源模型）；数据按项目隔离 |
| LLM API不稳定 | 服务中断 | 多模型备份（主备切换）；关键功能降级方案（退回人工模式）|
| 向量检索精度不够 | AI回答质量差 | 多路召回+重排序；持续优化分块策略；人工标注优化 |

### 9.2 业务风险

| 风险 | 影响 | 应对策略 |
|------|------|---------|
| 用户排斥AI | 推广困难 | 先从内部PM试用，再推广到客户；AI作为辅助工具而非替代 |
| 知识库冷启动 | 初期AI表现差 | 组织老PM进行知识贡献；历史项目资料批量导入 |
| 过度依赖AI | 团队能力退化 | 保持关键环节人工参与；定期进行无AI演练 |
| 行业特殊性 | 通用AI不适用 | 持续投入行业知识库建设；行业专家参与Prompt调优 |

#### 9.3.2 各智能体模型分配总览

| 智能体 | 主模型 | 备用模型 | 选型理由 |
|--------|--------|---------|---------|
| 项目调度Agent | 通义千问 | Claude | 需要综合评估能力，千问中文理解强 |
| 调研分析Agent | 通义千问 | Claude | 文档生成+信息结构化，千问擅长 |
| 计划生成Agent | 通义千问 + Claude | — | 千问生成文档，Claude做复杂推理 |

| 数据治理Agent | 通义千问(清洗) + Claude(校验) | — | 标准化用千问；跨表勾稽推理用Claude |

| 交付报告Agent | 通义千问 | — | 中文报告生成，千问表现优异 |

| **智能录入Agent** | **GLM**(答疑) + 千问(视频匹配) | — | 实时交互用GLM；内容理解用千问 |

#### 9.3.3 LLM网关路由策略

```
LLM网关路由设计:

请求进入 → 场景标识解析 → 模型路由
                              │
                ┌──────────────┼──────────────┐
                ▼              ▼              ▼
            GLM集群        千问集群        Claude API
          (私有化部署)    (API/私有化)      (API调用)
                │              │              │
                └──────────────┼──────────────┘
                               ▼
                          统一响应格式

路由规则:
1. 场景优先: 根据请求的agent_id和task_type确定主模型
2. 降级策略: 主模型超时/异常时自动切换到备用模型
3. 成本控制: 简单任务强制路由到GLM，避免使用高成本模型
4. 负载均衡: GLM和千问私有化实例间做负载均衡
5. 限流保护: Claude API设置请求频率限制和月度预算上限
```

#### 9.3.4 成本优化策略

| 策略 | 说明 |
|------|------|
| GLM私有化部署 | 客服/问答等高频场景使用私有化GLM，消除API调用成本 |
| 千问分级部署 | 简单任务用Qwen-7B/14B本地部署，复杂任务才调用Qwen-Max API |
| Claude按需调用 | 仅在需要深度推理的场景调用Claude API，严格控制Token用量 |
| 结果缓存 | 相同/相似查询结果缓存复用（如FAQ回答、标准化规则） |
| Prompt优化 | 持续优化Prompt减少Token消耗，使用Few-shot而非长指令 |
